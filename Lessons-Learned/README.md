
# Project Leadership, Reflections and Lessons Learned

# Project Background

*Project: Zero Trust SSO Integration – Microsoft Entra ID and AWS  
*Programme: TechStylers Microsoft Cloud Security Bootcamp (Identity, Data & AI)  
*Team: Helix Group  
*Role: Team Lead  
*Completion Date: June 2025

# 1. My Role as Team Lead

I served as the Team Lead of Helix Group during our TechStylers Bootcamp Final Project.

My leadership role involved coordinating our collaborative project activities, supporting communication among team members, and contributing to the team's overall project delivery.

Our project focused on implementing a Zero Trust identity management solution using Microsoft Entra ID and AWS.

The technical work described in this portfolio represents our collective team effort.

# 2. Technical Skills Developed

# Identity and Access Management (IAM)
- Understanding Microsoft Entra ID identity management.
- Working with AWS IAM roles and trust relationships.
- Applying group-based Role-Based Access Control (RBAC).
- Understanding least-privilege access.

# Identity Federation
- Understanding SAML-based Single Sign-On.
- Exploring identity provider and service provider integration.
- Learning how trust relationships and role mappings affect federated access.

# Zero Trust Security
- Configuring Multi-Factor Authentication.
- Implementing Conditional Access policies.
- Successfully demonstrating location-based sign-in restrictions.
- Understanding the importance of verifying access requests.

# Cloud Security
- Working with Microsoft Entra ID and AWS.
- Participating in cross-cloud identity and access management activities.
- Successfully demonstrating access to Azure resources through AWS during the final presentation.

# 3. Challenges Encountered

One of our main technical challenges was an unsuccessful AWS Console federated login despite generating a SAML token.

The experience highlighted the importance of correctly configuring IAM permissions, federation metadata, and trust relationships.

It also demonstrated that successful authentication does not necessarily guarantee successful authorization.

# 4. Successful Project Demonstrations

During the final presentation, our team successfully demonstrated:

1. Location-based Conditional Access enforcement that blocked a sign-in.
2. Access to Azure resources through AWS.

These outcomes were confirmed retrospectively by the Team Lead and are documented separately from the unsuccessful AWS Console SAML login recorded in the original presentation.

# 6. What I Would Improve in Future Projects

- Establish a detailed implementation and testing checklist.
- Assign and document individual technical responsibilities.
- Capture configuration evidence throughout the project.
- Test authentication and authorization separately.
- Record troubleshooting activities and their outcomes.
- Maintain project documentation from the beginning rather than retrospectively.

The project strengthened my understanding of Microsoft Entra ID, AWS IAM, SAML federation, Conditional Access, and Zero Trust security principles.

Beyond the technical experience, it helped me develop teamwork, communication, coordination, and problem-solving skills.
